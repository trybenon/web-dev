# Совместный просмотр видео

Учебный проект для синхронного просмотра видео в браузере.

## Структура

- client/ — клиент на React, TypeScript и Vite.
- server/ — HTTP-сервер на Node.js и TypeScript.
- shared/ — общий пакет типов и кода.
- docs/ — документация проекта.

Клиент и сервер подключают @watch-together/shared
как локальную зависимость через file:../shared.

## Подготовка

Нужны Node.js и npm.
Каркас проверен на Node.js 25.2.1 и npm 11.6.2.

Установка зависимостей из корня репозитория:

```bash
npm ci
```

## Разработка

```bash
npm run dev
```

Команда сначала собирает shared, затем запускает клиент и сервер.

- Клиент: http://localhost:5173/
- API через Vite: http://localhost:5173/api/health
- Сервер напрямую: http://127.0.0.1:3000/api/health

API проверки состояния возвращает {"status":"ok"}.

После изменения shared нужно перезапустить npm run dev,
чтобы пересобрать общий пакет.

## Сборка

```bash
npm run build
```

Пакеты собираются в порядке: shared, server, client.
Команда включает проверку типов TypeScript.

## Запуск собранного сервера

После сборки:

```bash
npm run start --workspace=server
```

Проксирование /api в конфиге Vite настроено для разработки.
Публикация приложения пока не настроена.

## Проверка кода и форматирование

Все команды выполняются из корня репозитория.

Проверка JavaScript, TypeScript и CSS:

```bash
npm run lint
```

Автоматическое форматирование:

```bash
npm run format
```

Проверка форматирования без изменения файлов:

```bash
npm run format:check
```

• ESLint использует общий корневой конфиг для client, server и shared.
• Stylelint проверяет CSS клиента.
• Prettier задаёт единое оформление кода и конфигураций.
• Документация в docs/ и отдельные спайки исключены из этих проверок.

## Unit-тесты

Однократный запуск:

```bash
npm run test
```

Запуск с повторной проверкой при изменении файлов:

```bash
npm run test:watch
```

Используется Vitest. Тесты находятся в client/src, server/src
и shared/src в файлах с окончанием .test.ts.

Пример: client/src/api.test.ts проверяет успешный ответ,
HTTP-ошибку и сетевую ошибку функции getHealth.
HTTP-запросы подменяются в тестах, запуск сервера не требуется.

## Покрытие тестами

Запуск тестов с отчётом о покрытии:

```bash
npm run coverage
```

Краткий отчёт выводится в терминал, HTML-отчёт создаётся в coverage/index.html.

Минимальный общий порог - 80% по каждой метрике: строки, функции, ветвления и инструкции.
При недостаточном покрытии команда завершается с ошибкой.

В отчёт включены исходники client/src, server/src и shared/src, в том числе файлы, которые ещё не импортируются тестами.

Исключены:

- тестовые файлы и файлы описаний типов .d.ts;
- client/src/main.tsx — подключение React к странице;
- server/src/index.ts — запуск сервера на фиксированном порту;
- shared/src/index.ts — сейчас содержит только интерфейс TypeScript.
  При добавлении исполняемой логики в исключённые файлы
  необходимо пересмотреть исключения.

Проверки серверных HTTP-ответов сами запускают локальный сервер
на свободном порту и закрывают его после завершения.
