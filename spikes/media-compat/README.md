# Спайк: звук MKV в браузере

Прототип проверки файла и кнопки «Исправить звук» плюс тестовые ролики и замеры.
Выводы и обоснование — `docs/spikes/media-compat.md`, полный разбор рынка
и источников — `docs/spikes/media-compat-research.md`.

Это не продукт: нет React, нет комнаты и синхронизации. В проект переносится
`src/verdict.ts` с тестами и подход из `src/app.ts`.

## Запуск

Нужен Node 22.18 или новее. Незнакомые слова — в словаре в конце этого файла.

```bash
npm install
npm run build      # собирает public/app.js и public/writer.worker.js
npm start          # http://localhost:8790
```

- `http://localhost:8790/` — прототип: выбрать фильм, посмотреть прогноз и проверку,
  нажать «Исправить звук», послушать результат, сохранить копию.
- `http://localhost:8790/check.html` — таблица «что браузер обещает и что играет»
  по 13 тестовым роликам.

Страница работает только с `localhost` или по HTTPS: хранилищу браузера (OPFS)
нужен безопасный контекст. Файл не уходит на сервер — сервер только отдаёт страницу.

## Тестовые ролики

```bash
npm run samples    # samples/: 01–13 (H.264) и vp9-* (для автоматической проверки)
MINUTES=120 AUDIO=ac3 bash tools/make-big-sample.sh   # длинный «фильм» для замера: ac3 | eac3 | dts
```

Ролики не хранятся в репозитории (папка `samples/` в `.gitignore`) — их делает скрипт.
Нужен ffmpeg с libx264, libx265, libvpx-vp9, libopus:

- macOS: `brew install ffmpeg`. Сборка Homebrew не умеет рисовать текст на кадре —
  ролики получатся без таймкода, на результат проверок это не влияет;
- Windows: `winget install Gyan.FFmpeg`, а сам `npm run samples` — из Git Bash (скрипт на bash);
- Linux: пакет `ffmpeg` из дистрибутива.

Короткие ролики занимают около 40 МБ. Длинные «фильмы» для замера — 3–4 ГиБ каждый,
на замер с двумя длинными файлами нужно около 10 ГБ свободного места (исходники плюс
результаты в хранилище браузера).

## Тесты и замеры

```bash
npm test                                              # 41 тест: 39 — 13 роликов × 3 браузера, ещё 2 — User-Agent и план конвертации
npm run bench                                         # конвертация VP9-роликов в Chromium + проверка звука
BIG=samples/big-120min-ac3.mkv CODEC=aac npm run bench   # плюс замер на длинном файле
```

`bench` запускает Chromium через Playwright. Один раз установите его:
`npx playwright-core install chromium` — или укажите путь к своему Chrome/Chromium
в `CHROMIUM_PATH`. В Chromium из Playwright нет H.264 и AAC, поэтому звук результата
там проверяется на VP9-роликах с Opus (`CODEC=opus`, по умолчанию). Конвертация H.264
работает и там: видео копируется, декодер не нужен. Короткий замер идёт около минуты,
с длинными файлами — 10–20 минут. Пиковую память браузера во время замера (только
Linux) пишет `python3 tools/rss.py results/rss.log` во втором терминале.

## Устройство

```
src/verdict.ts         прогноз «откроется ли / будет ли звук / какую дорожку выберет браузер»; чистые функции
src/app.ts             страница: чтение заголовка (Mediabunny), проверки, конвертация, проверка результата
src/writer.worker.ts   запись результата в OPFS через createSyncAccessHandle (есть во всех трёх браузерах)
public/index.html      страница прототипа
public/check.html      таблица кодеков: обещания браузера против факта
tests/verdict.test.ts  тесты прогноза на замерах из results/browsers-2026-10-06.md
tools/serve.mjs        статический сервер
tools/bench.mjs        автоматический замер в Chromium
tools/rss.py           пиковая память браузера во время замера (Linux)
tools/make-samples.sh, tools/make-big-sample.sh   генерация роликов
results/               отчёты браузеров и замеры скорости
```

Библиотеки: [Mediabunny](https://mediabunny.dev/) 1.61.3 (MPL-2.0) и расширения
`@mediabunny/ac3`, `@mediabunny/dts`, `@mediabunny/aac-encoder` — wasm-сборки
декодеров и кодировщика FFmpeg. Расширения содержат код FFmpeg (LGPL): при переносе
в продукт оставить их отдельными файлами и дать ссылку на исходники FFmpeg.

## Словарь

- **OPFS** (Origin Private File System) — приватное хранилище файлов браузера для сайта.
  Пользователь его не видит; туда пишется исправленный файл, оттуда его можно сохранить.
- **WebCodecs** — API браузера для прямого доступа к его кодекам (декодерам и кодировщикам).
- **wasm** (WebAssembly) — скомпилированный код, который браузер выполняет почти
  с родной скоростью. Здесь так работают декодеры AC-3, DTS и кодировщик AAC из FFmpeg.
- **Демультиплексор** — часть плеера, которая разбирает контейнер (MKV, MP4)
  на отдельные дорожки видео и звука.
- **canPlayType** — вопрос к браузеру «смогу ли сыграть такой тип файла»; ответ —
  «да», «может быть» или «нет».
- **MSE** (Media Source Extensions) — способ подавать видео в `<video>` кусками из кода.
- **fMP4** — фрагментированный MP4: файл из независимых кусков, удобен для MSE.
- **rVFC** (`requestVideoFrameCallback`) — сообщает, какой кадр и когда показан;
  им пользуется наша синхронизация.
- **× реального времени** — во сколько раз обработка быстрее просмотра: при 16× двухчасовой
  фильм обрабатывается за 7,5 минут.
